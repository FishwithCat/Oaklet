# SQLite 索引持久化与重启恢复：实现与验证

日期：2026-11-18。对应主计划步骤 5；查询缓存及 Agent 工具仍在步骤 6–7。

## 实现

- 新增 `V1__code_index.sql`，创建 projects、files、symbols、evidence、queries 五张 `code_index_` 表及 B-tree 索引。保留 V0 和既有迁移 runner。后两张表本步只建立结构，查询缓存写入在步骤 6，IPC 证据提取在步骤 9。
- 桌面 setup 只打开一次 `oaklet.db`，向 `ChatState::from_store` 和 `CodeIndexManager::with_store` 注入同一个 Store 的克隆。聊天仍在初始化时恢复中断的 run。无 Store 的 `new` 保留给已有独立协议探针。
- SQL 集中在 `store/code_index.rs`。工程清理只删除当前工作区的派生项目及级联行，不访问聊天表；文件内容 hash、提取状态和符号在单文件事务内替换。符号保存业务类型、名称、种类、容器及 UTF-16 范围，不保存源码或 LSP 消息。
- 工作区拥有独立的持久化后台任务，关闭时取消并等待任务退出，磁盘索引保留。所有数据库操作在 `spawn_blocking` 中执行；磁盘读取、BLAKE3 和 LSP 请求不占数据库锁。短写事务前持工作区锁核对 generation/revision，禁止关闭重开后的旧任务回填。
- 打开时异步恢复上次项目摘要，先标为待核对；现有 watcher 启动后才会开始内容核对。首次打开重新 hash 所有发现的受支持源码及项目配置/锁文件，不以 mtime/size 推断跨重启内容一致。
- 当前会话保留有界于发现清单的 hash 元数据，不保留源码。普通源码变更只重新读取脏文件；配置、成员变化、监听故障等需要重新发现的情况保守全量核对。稳定快照由排序后的相对路径、内容 hash、后端命令/版本/工具链/SDK 指纹和格式版本生成；首版将工作区源码/配置摘要纳入各项目快照，允许额外失效，避免遗漏工作区内共享配置。
- 同内容且后端指纹一致的文件复用已提取符号。变化文件先清空旧位置再提取，删除/重命名/ignore/项目消失清理旧行；后端指纹或格式版本变化使对应项目重新提取。监听补充覆盖 `rust-toolchain*` 与 `.cargo/config*`。
- 后台按文件请求 documentSymbol：不在交互请求前排队、不为后台任务驱逐或启动其他服务器；交互查询到来时取消后台请求并让出实例。单次提取最多 3 秒，等待启动或交互资源最多 70 秒，超限记录跳过原因。临时打开的文档在请求结束后关闭，已有交互文档保留。
- 落盘前同时核对扫描 hash、实际提交给 LSP 的文档文本 hash、再次读取的磁盘 hash 及 generation/revision。派生符号 JSON 损坏或提取标记对应的符号缺失时，只丢弃该文件的符号并重新调度。数据库写入失败记录持久化错误，实时查询仍沿用原路径。
- 状态分别记录磁盘核对、后台提取、发现文件数、已处理/已提取/复用/跳过文件数、恢复项目数及快照；磁盘 verified 不代表语义分析完整。空符号不持久标记为有效提取；能力缺失、超大文件等保留原因。IPC 一律明确未覆盖，步骤 9 接入提取规则与按文件调度。

## Acorn 真实后端验收

继续使用 `/private/tmp/oaklet-acorn-lsp-spike` 临时副本，不修改原始 Acorn。工具版本沿用步骤 1–4：rust-analyzer 1.99.1、typescript-language-server 6.1.0、TypeScript 5.9.3。

显式运行 core 单元测试二进制中的 `code_index::lifecycle_tests::real_project_sqlite_restore_probe --ignored --exact --nocapture`，环境为：

```sh
CARGO_HOME=/Users/linear/Workspace/Acorn/.cargo
PATH="/private/tmp/oaklet-lsp-spike-tools/node_modules/.bin:$PATH"
OAKLET_INDEX_PROJECT=/private/tmp/oaklet-acorn-lsp-spike
```

该探针只接受临时目录内的工程，单独创建临时 SQLite；首次提取后关闭全部服务、重新打开数据库与 manager，再核对相同快照和复用文件数，结束时删除临时数据库。须分别验证每个项目语言有非空提取结果，不能用两种语言合计掩盖后端失败。

| 阶段 | 源文件 | 已提取非空符号 | 复用文件 | 跳过文件 | 恢复项目 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 首次落盘 | 217 | 167 | 0 | 50 | 0 |
| 关闭重开并核对 | 217 | 168 | 167 | 49 | 2 |

最终观测中，Rust 首次提取 167 个文件中的 120 个，重开后复用这 120 个并新提取 1 个；TS 两轮均为 50 个文件中的 47 个。其余文件返回空符号，保持完整性未知，不视为“没有符号”的已验证负结果。重复运行的早期空结果数量会波动，验收要求此前已提取文件全部复用，并允许上次空结果新增覆盖；不要求覆盖数恒定。最终观测首次 3626ms，重开 2584ms，均包含服务器关闭；机器缓存已热，不代表无依赖缓存的冷启动，也不是 SLA。

最终日志保存于 `/private/tmp/oaklet-acorn-index-persistence.txt`，另核对临时副本的源文件 hash 未变，且没有新增遗留语言服务器进程。

验收暴露并修复了首次 didOpen 后额外发送 didSave 的问题：rust-analyzer 在早期加载期间会因此崩溃。现在首次打开只发 didOpen；已有文档磁盘内容变化才发送 didChange 和所声明的 didSave。假服务器声明保存能力并验证首次打开无保存通知、实际保存有通知。

## 边界

- 只持久化源文件符号与相关配置的快照；没有引用/调用缓存、完整调用图或 IPC 证据。项目外依赖状态仍不能证明完整，后续语义缓存必须继续遵守就绪门槛。
- 读取仍受步骤 4 的 UTF-8、单文件 8 MiB 和路径边界限制；跳过项有原因，快照核对失败不能标成 verified。
- 恢复符号不代表语言服务器已完成语义分析。查询读取持久结果的入口及容量/过期清理在步骤 6，前端展示在步骤 8。
- 未做 GUI 手工流程及 Windows/Linux 原生监听实测；desktop 构建仍有大 chunk 提示。
