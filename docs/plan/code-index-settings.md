# 工作区索引状态与设置：实现及验证

日期：2026-11-18。对应主计划步骤 8。未增加依赖或数据库迁移。代码已提交为 cd996b6。

## 实现

- `code_index/commands.rs` 注册 `code_index_status`、`code_index_retry`、`code_index_rebuild`。先确认窗口仍在注册表，再通过 `workspace_for_window` 取得当前工程；不接收任意工作区路径。重试参数为项目根和语言，须匹配该工作区已经发现的项目，避免同根 Rust/TS 互相重试。重建直接调用步骤 6 的 Service，不清理源码或聊天数据。
- `WorkspaceStatus` 补充当前工作区根，`ProjectStatus` 补充服务器版本。展示修订号与文件变更 revision 分开：序列化状态内容、工作区 generation 和文件 revision 一起用于变化判断，发生变化才分配单调递增的展示 revision。服务器状态、进度、持久化与缓存变化都能更新展示；关闭后重开仍取得更大的修订号。
- 单个宿主任务每 500 ms 合并采样打开窗口的状态，只在修订号变化时通过 `emit_to` 发送 `code-index://changed`；发送期间持有窗口注册表锁，已移除的窗口不会收到通知，也不会把本工程状态广播到其他工程。销毁窗口后清理其发送记录，应用退出就绪后结束任务。短暂的中间进度可能被合并，不承诺逐条转发 LSP 进度。
- 前端使用当前窗口的监听器，先订阅事件再调用快照命令，事件与快照共用修订号过滤；忽略旧/重复状态、卸载后的迟到快照，并释放异步注册完成的监听器。订阅或快照失败显示错误；后续事件仍可恢复状态。
- 设置页新增 **Code Index** 页签，沿用现有表单和保存流程。Rust 与 TS/JS 分别设置启用开关、可执行文件和 JSON 参数数组；参数按数组传递，不拼 shell。非法 JSON 禁止保存，切换页签保留输入与错误；命令、参数组合及 NUL 仍由 Rust 配置验证兜底。
- 当前工程区域展示发现/监听状态、项目根与语言、服务器版本、实际能力与服务器进度、启动/等待/失败原因，以及按项目的磁盘核对、恢复项目数、文件符号覆盖数、复用/跳过计数和缓存错误。协议 Ready 明确显示语义完整性未知；SQLite/文件索引复用不会被写成实时分析完成，没有服务器进度时不展示百分比。
- 提供按项目语言重试与当前工程清除重建入口。界面明确说明后端需自行安装及 Rust/TS 运行环境要求；安装入口仍留在步骤 12。

## 配置更新与并发边界

全局保存经原有 `config_write` 串行化，再通知共享 manager。manager 保留最新全局配置，保证同时新开的工作区、尚在启动中的工作区和正在重建的工作区最终使用最新配置。

每个工作区用现有后台任务的 watch channel 串行处理配置和文件刷新；配置变化立即使旧查询/缓存失效并进入核对状态。只退休有效配置发生变化的语言实例，其他语言的健康实例继续复用。配置通道合并多次保存，完成旧刷新时仍有待应用配置就保留 stale；后续文件事件读取最新配置，不再捕获首次打开时的旧配置。缓存按工作区保守失效，持久层继续依据内容和后端指纹核对。

重试完成检测后再次核对配置，拒绝把已被新设置替代的检测结果注册回去。重试检测到版本变化时退休旧指纹实例，避免旧进程留在池中。关闭时仍由已有取消、generation 校验与 drain 收回工作区任务和进程。
