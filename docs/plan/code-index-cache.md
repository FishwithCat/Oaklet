# 查询缓存、失效与重建：实现与验证

日期：2026-11-18。对应主计划步骤 6；Agent 工具与界面分别在步骤 7、8 接入。

## 实现

- `code_index/cache.rs` 接入共享 Rust Service；沿用标准 `HashMap`、BLAKE3 和既有 Store，不增加依赖、迁移或通信层。生产服务必须使用注入 Store 的 manager，独立协议探针仍可使用不持久化的 `new()`。
- 文件符号依次读取内存、`code_index_queries`、`code_index_files` 中的有效符号，最后请求 LSP。文件索引提供首次查询与重启后的恢复来源。返回 `source` 为 `live`、`memory`、`sqlite` 或 `file_index`，`coverage` 分别标记目标文件内容、项目快照和语义就绪；`completeness_known` 与 `truncated` 保留，不把命中标成完整分析。
- 当前 Rust/TS 后端没有可靠的语义完整度依据，定义、引用和调用查询始终走实时路径，不读写查询缓存。实时路径返回前仍会重新读取并 hash 查询文件，与 LSP 提交文本的 hash 不一致时返回 not_ready，成功时填写 `file_verified`，项目快照已验证时填写 `project_verified`，`semantic_ready=true` 表示实时后端已回答；这不构成完整索引证明，`completeness_known` 继续为 false。非空结果、协议 Ready、固定等待、TTL 或连续相同结果均不构成完整度证明；`semantic_cache_enabled` 明确为 false。文件符号只证明对应源码内容一致，完整性仍未知。
- 缓存键包含规范化的工作区、项目、语言、完整 Query 参数、项目快照、后端命令/版本/工具链/SDK 指纹、目标文件内容 hash 和格式版本，使用 BLAKE3。绝对路径与等价相对路径产生相同键。generation/revision 用于请求与写入前后的时序检查，不作为可跨重启复用的稳定身份。
- 每次符号查询均重新读取并 hash 磁盘文件；返回前再次核对 hash、generation/revision、stale 和取消状态。实时结果还核对实际提交给 LSP 的文本 hash。内容不同即使 mtime/size 相同也不能命中旧结果；发现内容尚未纳入项目快照时不写查询缓存。缓存中的符号必须全部属于该目标文件，不能用单文件 hash 验证其他文件的位置。
- 仅对核对过项目快照和后端环境的非空文件符号启用查询缓存，内存全局最多 256 条、序列化结果负载最多 16 MiB，按访问序号淘汰。查询结果最多复用 10 分钟；内存/SQLite 命中不续期，SQLite 命中以原创建时间进入内存。有效的文件索引可在重新核对内容后重新生成查询结果。
- 源码、重命名、删除、ignore、配置、锁文件、工具链配置以及监听故障/溢出复用现有 watcher 与 revision 路径，保守清空当前工作区内存缓存。持久层在新快照或环境指纹落盘时删除旧查询；重新核对前不读取这些查询。项目快照仍保守包含整个工作区输入，因此允许额外失效。
- 后端检测失败时保留上次文件符号，逐文件核对内容后可返回 `file_index`；此时不启用查询缓存，项目/环境覆盖不能视为已验证，定义/引用/调用继续报告后端不可用。明确禁用语言仍遵守禁用配置。后端恢复后使用实际环境指纹重新核对或提取。
- SQLite 派生数据按逻辑负载 256 MiB 软上限清理：先删过期查询，再按访问时间淘汰查询，仍超限才清理最近未使用的关闭工程；关闭工程 30 天未访问可回收。打开工程的文件索引受保护，故活动数据自身超过上限时保留并允许超过软上限。核对完成、查询写入及工作区关闭时触发清理；关闭时记录访问时间。只访问 `code_index_` 表，不清理聊天、迁移记录，不执行 VACUUM，也不保证 SQLite 物理文件立即缩小。
- 存储读取/写入失败记录缓存错误并回退；缓存写失败不能撤销成功的实时结果。坏查询 JSON 只删除该查询，仍可从有效文件索引恢复。数据库工作使用 `spawn_blocking`，文件读取、hash、LSP 不占数据库锁；短写入及清理时核对工作区身份并保护活动工程。
- 新增 `CodeIndexManager::rebuild`：先替换 generation、增加 revision、标记 stale、取消旧任务/会话并清内存，再只删除当前工程派生行，重新打开并发现/提取。清理失败仍恢复服务并返回错误；清理前复查 generation，不能清掉关闭重开后的新工程。重建由独立任务完成，调用方放弃等待不会留下半完成状态。前端 command 和按钮留在步骤 8。
- 重建验收暴露并修复 LSP 关闭竞态：协议任务收到 abort 到实际退出之间保留 socket，避免内部发送通道提前关闭导致 async-lsp 后台 panic；测试等待协议任务并拒绝 panic。

## 自动验证

core 完整测试通过（351 项，另有 1 项默认忽略的真实后端探针单独运行）；严格 `cargo clippy --all-targets --offline --locked -- -D warnings`、`cargo fmt --all -- --check` 以及 LSP 穿刺示例 3 项测试通过。覆盖：

- 文件索引、内存、SQLite 命中及跨数据库重启恢复；等价路径归一化；来源与未知完整性标记。
- 条数/负载边界、LRU、10 分钟 TTL、命中不续期、过期及未来时间数据拒绝。
- 同 mtime/size 内容变化、项目快照/后端升级、过期快照的迟到写入拒绝；沿用原生 watcher 的变更/重命名/删除、工具链配置、溢出和恢复回归。
- 空结果不缓存，非空定义连续两次仍请求后端；跨文件符号不允许单文件缓存。
- 查询期间保存文件返回未就绪，重建期间旧代查询返回关闭；调用方放弃重建等待后流程仍完成。
- 缓存写故障仍返回实时结果；坏查询 JSON 回退文件索引；后端缺失仅返回核对过的文件符号。
- 先淘汰查询再淘汰关闭工程、30 天回收、活动工程保护；仅重建当前工程，其他工程、聊天和源码不变。

数据库结构与迁移 runner 没有改动；测试故障触发器单独存放在 SQL fixture。未改前端，本步未重复 desktop 测试/构建；未做 GUI 或 Windows/Linux 原生监听实测。
