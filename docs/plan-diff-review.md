# Oaklet Diff View 实施计划

先把 Source Control 的 **Changes** 和 **Commits** 做成适合连续审阅多个文件的视图。用户能看到改动范围，快速切换文件和变更块，并按需展开上下文。先用现有工作区和历史提交验收，再决定是否接入隔离任务。

## 用户流程

| 场景 | 预期行为 |
| --- | --- |
| 查看当前改动 | 打开 **Changes** 后，左侧固定显示工作区的变更文件，右侧显示选中文件的 Diff。切换文件时，文件列表的位置和焦点保持可用。 |
| 审阅历史提交 | 在 **Commits** 选择提交后，提交摘要下显示固定的变更文件列表。列表和 **Changes** 使用同一套浏览交互。 |
| 连续查看改动 | 用鼠标或键盘选择文件，在 Diff 中跳到上一个或下一个变更块。跳到长文件末尾的变更块时，直接加载目标附近的内容。 |
| 查看周边代码 | 点击变更块之间或文件首尾的折叠行，分批展开未改动的上下文。展开后保留当前阅读位置，显示正确的新旧行号。 |

## 1. 固定变更文件列表

- 复用 Source Control 左侧的可调宽度区域。**Changes** 显示文件列表，**Commits** 在同一区域内显示提交选择和所选提交的文件列表。按目录和路径稳定排序，支持按路径筛选。显示新增、修改、删除和重命名，重命名可查看原路径。已有可靠的增删行统计时在列表中显示。
- **Changes** 复用现有状态列表和单文件 Diff。**Commits** 先取所选提交的变更文件元数据，再取选中文件的补丁。文件列表的加载与单个补丁的大小分开，单文件补丁继续应用现有大小上限。历史提交沿用现有的比较语义，合并提交以第一父提交为基线，根提交以空树为基线。
- 保留当前选中的文件。刷新后若该文件仍存在，就继续选中它。如果文件已消失，选中列表中的相邻文件。按工作区、视图、提交和路径匹配请求结果，防止快速切换或刷新时显示过期内容。补丁超限、加载失败、二进制和只有文件元数据变化分别显示对应状态，文件列表仍可继续浏览。
- 保留 Files 编辑器调用的 `git_diff` 接口及其行号行为。提交按文件取补丁后，符号查询和图片预览也使用该文件对应的版本。[Source Control](../packages/desktop/src/features/source-control/SourceControl.tsx) · [数据加载](../packages/desktop/src/features/source-control/useSourceControl.ts) · [Git 读取](../packages/core/src/git.rs)

## 2. 按变更块导航

- 继续使用统一 Diff 和新旧行号，在变更块标题里显示受影响的符号。文件列表支持方向键选择。Diff 提供上一个和下一个变更块入口，文件边界处可继续到相邻文件。使用 ⌥↑ 和 ⌥↓ 跳转，快捷键仅在 Diff 区域获得焦点时生效，输入筛选词时保留正常编辑行为。
- 使用现有解析得到的变更块顺序。长文件按块分批渲染，跳转时直接渲染并聚焦目标块附近，保留现有的内容上限。按块加载前后内容时，校对行号及顺序，确保每一行都可到达。[Diff View](../packages/desktop/src/features/source-control/Diff.tsx) · [Diff 解析](../packages/desktop/src/features/source-control/git-diff.ts)

## 3. 按需展开上下文

- 根据变更块的新旧行范围，在文件首尾和块之间显示可展开的未改动行。每次请求有限的行数，复用 Diff 行的渲染。先用统一视图验收，再根据实际使用决定是否增加左右对照。
- 上下文与生成当前补丁的文件版本绑定。历史提交从对应的 Git 对象读取。工作区新版本若需从磁盘读取，沿用窗口工作区校验，并核对内容与补丁记录的版本一致。文件在审阅期间变化时，提示刷新后再展开。对缺失版本、超限文件和不适用的文件类型，继续展示已有 Diff 或预览。[上下文与符号的版本校验](../packages/core/src/git/review.rs)

## 验收

| 验收场景 | 通过条件 |
| --- | --- |
| 多文件 Changes 和 Commits | 选择一个包含多个目录的工作区变更或提交，可筛选并连续浏览文件。提交范围内所有文件可见，包含大补丁时仍能打开其他文件。 |
| 文件状态与路径 | 新增、删除、仅暂存、未跟踪、重命名、二进制、图片和仅模式变化各自可读。带空格和 Unicode 的路径能定位到正确文件。 |
| 历史基线 | 普通提交、根提交和合并提交的补丁及上下文与对应 Git 版本一致。 |
| 长文件和符号 | 直接跳到原来需要多次点击加载的变更块。前后跳转、展开上下文后，行号和阅读位置正确，变更块标题显示对应的符号。 |
| 快速切换与外部编辑 | 连续切换文件或提交时，迟到的响应不会替换当前视图。工作区文件在展开前变化时，提示重新加载。 |
| 只读审阅 | 打开 Diff、切换、刷新和展开前后，工作区文件及 Git 暂存区内容一致。Files 的变更行标记继续可用。 |

复用桌面 Diff 解析测试和 Rust 临时 Git 仓库测试，覆盖新引入的文件选择、直接跳转、按文件读取和版本过期行为。在原生 macOS 应用里走一遍多文件键盘审阅、长文件展开和外部修改后的刷新流程。

```sh
pnpm --dir packages/architecture-helper build
(cd packages/core && cargo test && cargo clippy --all-targets)
pnpm --dir packages/desktop test
pnpm --dir packages/desktop build
```

## 后续接入隔离任务

首版的 **Changes** 继续展示当前工作区的全部改动。聊天里的「查看本次改动」需要先能可靠识别任务自己的改动。以后若用独立 worktree 执行任务，可以把它打开为普通工作区窗口，让聊天、终端、文件树和 Git 共用该目录。任务审阅复用这套视图，对比启动时的固定基线和任务结果。把改动应用回原工作区前，再针对目标工作区的最新内容做预检。
