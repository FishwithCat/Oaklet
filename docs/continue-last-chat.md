# 「继续上次」功能方案

打开工作区时，自动回到上次查看的、至少成功发送过一条消息的会话。直接显示最新一页记录，用户可以在原会话里继续提问。

## 打开工作区时的行为

| 情况 | 行为 |
| --- | --- |
| 记得上次查看的会话，且它仍在当前工作区的历史中 | 打开该会话，即使另一条会话最近才更新过。 |
| 首次升级、偏好不可读取，或记住的会话已不存在 | 打开当前工作区历史中最近更新的会话。 |
| 工作区没有历史 | 按现有流程创建空白聊天。 |
| 历史或会话读取失败 | 显示恢复失败提示，允许重试或新建聊天。保留已有历史和上次会话偏好。 |

- 每个工作区只恢复一个标签。空白标签和未发送的草稿仍随窗口关闭而结束。打开或关闭空白标签时，保留最近一次有消息的会话记录。
- `⌘N` 仍可新建聊天，`⌘R` 仍可打开历史。手动打开一条有消息的旧会话后，它成为下次恢复的目标。
- 如果上次运行因应用退出而中断，显示已保存的内容和已有的中断提示。下一轮由用户发消息触发。

## 实现步骤

1. **记录会话 ID。** 在 `useAgentSession` 中，以后端返回的规范化工作区路径为键，用 `localStorage` 保存一个会话 ID。切换到已保存的会话时写入。空白会话的第一条消息经后端确认后，如果会话仍是当前标签，也写入。使用后端返回的 `turns > 0` 判断，避免记住发送失败的消息或由后台更新的标签。存储读写失败时，继续使用现有会话功能。
2. **复用启动时的历史查询。** `session_list` 已按工作区过滤掉空白会话，并按 `updated_at` 倒序返回。记住的 ID 仍在列表里时选它，否则选第一条。用现有的 `session_get` 读取最新一页，再走 `addTab` 激活。原有 Rust 命令继续校验工作区归属，方案沿用 SQLite 里的会话数据，前端只保存选中的 ID。
3. **处理等待和失败。** 首次加载期间显示短暂的加载状态，等真实标签就绪后再接收草稿和附件。启动请求使用当前工作区及请求身份校验，避免重复初始化、旧响应覆盖已打开的标签。列表或会话读取失败时，复用现有错误展示样式并提供「重试」和「新建聊天」。如果出错后重新查询确认目标已经从列表消失，按上表重新选取。主动新建后，迟到的恢复结果应被丢弃。
4. **更新文档。** 修改 README 的 Chat 和 Status 段落，说明启动时恢复一个会话，以及新建、历史和草稿的行为。

涉及入口为 [会话状态及启动流程](../packages/desktop/src/features/chat/useAgentSession.ts)、[聊天界面](../packages/desktop/src/features/chat/Chat.tsx)、[窗口绑定的会话命令](../packages/core/src/chat/commands.rs)和[会话历史查询](../packages/core/src/store/sessions.rs)。

## 验收

- **恢复上次查看的会话。** 先在 A 发消息，再切到较早的 B，最后打开一个空白标签。关闭应用并重新打开工作区，确认回到 B，且只打开一个标签。
- **验证回退。** 清除偏好或写入失效 ID，确认恢复当前工作区最近更新的会话。打开一个没有历史的工作区，确认只创建一个空白标签。
- **验证工作区隔离。** 分别在两个工作区选择会话，再分别重开。确认各自恢复，另一工作区的会话 ID 即使误写进偏好也无法打开。
- **验证中断与长会话。** 打开有中断记录的长会话，确认可看到提示、可加载更早记录，且应用在打开会话时没有发起模型请求或执行工具。
- **验证失败与并发。** 模拟 `session_list` 和 `session_get` 失败，确认能重试或新建。模拟恢复响应延迟，确认它不会覆盖用户打开的新标签，也不会生成重复标签。

实现时，在桌面现有测试中覆盖会话选择规则，再运行 `pnpm --dir packages/desktop test` 和 `pnpm --dir packages/desktop build`。用 macOS 桌面应用验证实际退出重开后的恢复行为。
